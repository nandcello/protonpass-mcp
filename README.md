# Proton Pass CLI MCP

A small stdio MCP server that exposes seven Proton Pass and SimpleLogin actions:

- `search_aliases` searches account-wide aliases and returns a page of matches.
- `create_alias` creates a hide-my-email alias and returns its address.
- `get_or_create_alias_contact` gets or creates a contact for an alias and returns its reverse-alias address.
- `create_login` creates a login item with a password generated inside Proton Pass.
- `get_totp` returns the current one-time code or codes for a login item.
- `find_logins` lists logins in the configured vault without revealing secrets.
- `get_login_credentials` reveals the username, email, and password of one login
  in the configured vault so an agent can sign in. Every reveal requires
  approval, is audited, and is rate limited.

The password generated by `create_login` is never passed into the MCP server and
is never returned to the model. The server invokes Proton Pass CLI's
`--generate-password` option so the password is generated and stored by Proton
Pass itself.

## Requirements

- [Vite+](https://viteplus.dev/) (`vp`)
- Bun 1.3.14 (resolved automatically by Vite+)
- Node.js 20 or newer (managed by Vite+)
- [Proton Pass CLI](https://proton.me/blog/proton-pass-cli) available as
  `pass-cli`
- An authenticated Proton Pass CLI session
- A SimpleLogin API key for `search_aliases` and `get_or_create_alias_contact`

Authenticate before starting the MCP client:

```sh
pass-cli login
pass-cli info
```

Copy `.env.example` to `.env` and add a SimpleLogin API key:

```sh
cp .env.example .env
```

The server loads `.env` from its project directory without overriding variables
already provided by the parent process. `.env` is ignored by Git; only
`.env.example` is tracked.

## Install and test

```sh
cd /path/to/protonpass-mcp
vp install
vp check
vp run test
```

Vite+ delegates package installation and dependency changes to the Bun version
pinned in `package.json`. Use `vp add`, `vp remove`, and `vp update` for normal
dependency maintenance; use `vp pm <command>` when a Bun-specific package
manager command is needed. `bun.lock` is the only package-manager lockfile for
this project.

## Add to Codex

Register the local stdio server:

```sh
codex mcp add protonpass \
  --env PROTONPASS_CLI_PATH=/absolute/path/to/pass-cli \
  -- node /absolute/path/to/protonpass-mcp/src/index.js \
  --share-id VAULT_SHARE_ID
```

Alternatively, add it to `~/.codex/config.toml`:

```toml
[mcp_servers.protonpass]
command = "node"
args = [
  "/absolute/path/to/protonpass-mcp/src/index.js",
  "--share-id",
  "VAULT_SHARE_ID",
]

[mcp_servers.protonpass.env]
PROTONPASS_CLI_PATH = "/absolute/path/to/pass-cli"
SIMPLELOGIN_API_KEY = "YOUR_SIMPLELOGIN_API_KEY"
```

Restart the MCP client or start a new task after changing its MCP
configuration.

Exactly one vault selector is required when the server starts:

- `--share-id VAULT_SHARE_ID` selects a vault by its unique share ID and is
  recommended.
- `--vault-name VAULT_NAME` selects a vault by name. The name is resolved to its
  share ID once, and the server refuses to run Proton Pass tools if it matches no
  vault or more than one.

Find a vault's share ID with `pass-cli vault list`. The selected vault is fixed
for the lifetime of the server. Vault selectors are operator configuration, are
not exposed as tool inputs or results, and every Proton Pass CLI command receives
the selected vault's `--share-id`.

`search_aliases` and `get_or_create_alias_contact` are exceptions to vault
scoping: Proton Pass CLI does not expose alias search or alias-contact
operations, so these tools use the account-wide SimpleLogin API. The API key can
access aliases outside the selected Proton Pass vault.

## Login credentials and the vault lock

`find_logins` and `get_login_credentials` only ever read the vault chosen with
`--share-id` or `--vault-name` when the server starts (for example, a dedicated
`AGENT` vault). Anything saved in that vault can be revealed; nothing in any
other vault can:

- No tool input can name or select a vault. Tool schemas are strict, so inputs
  such as `shareId`, `vaultName`, or `vault` are rejected.
- A `--vault-name` is resolved to its share ID once, with
  `pass-cli vault list --output json`. The server refuses to continue if the
  name matches no vault or more than one (Proton Pass CLI would silently pick
  the first).
- Every `item list` and `item view` call passes `--share-id` with the locked ID.
- Every `item view` result is checked again: if its `share_id` is missing or
  differs from the locked ID, the server refuses and returns nothing. `item list`
  rows from other shares are dropped. Items shared with your account
  individually (rather than saved in the locked vault) have their own share ID
  and are therefore refused; move or copy them into the vault instead.

`get_login_credentials` returns only `id`, `title`, `username`, `email`,
`password`, and `urls`. Notes, TOTP secrets and URIs, passkeys, custom and extra
fields, attachments, and history are stripped. `find_logins` returns no secret at
all, only whether a username or email is saved.

### Approval for every reveal

Revealing a password does not change the vault, but `get_login_credentials` is
deliberately annotated `readOnlyHint: false`, `destructiveHint: true`, and
`idempotentHint: false`. MCP clients such as Executor ask for human approval
before running tools that are not read-only, so the owner approves each reveal
individually. `find_logins` is read-only and needs no approval.

### Audit log and rate limit

Each `get_login_credentials` attempt appends one JSON line to the audit log
with the timestamp, tool, outcome (`success`, `refused`, or `error`), a reason
code, and the item ID and title or the looked-up host. Usernames, emails, and
passwords are never written. The log is created with mode `0600` (its new
directory with `0700`). If the entry for a successful reveal cannot be written,
the call fails closed and returns no password.

Reveals are limited to 5 per rolling hour by default; further reveals are
refused (and audited as refused). The counter is held in memory by the server
process, so it is shared by every connection to that process and resets when
the process restarts.

Every Proton Pass CLI call made by these tools sets `PROTON_PASS_AGENT_REASON` to
a fixed, server-generated `protonpass-mcp sign-in for <item title or host>`
(control characters removed, at most 300 characters), which appears in
`pass-cli agent monitor`.

### Agent token setup

Proton Pass agent tokens can be limited to one vault and expire on their own.
From an account session, create an agent with access to the vault only:

```sh
pass-cli agent create protonpass-mcp --expiration 3m --vault AGENT
```

Then sign in as that agent in a separate session directory, so the server's
session does not replace your own:

```sh
export PROTON_PASS_SESSION_DIR=/path/to/protonpass-mcp-session
PROTON_PASS_PERSONAL_ACCESS_TOKEN='pst_...' pass-cli login
pass-cli info
```

Start the MCP server with the same `PROTON_PASS_SESSION_DIR` and
`--vault-name AGENT` (or the vault's `--share-id`). Agent sessions require
`PROTON_PASS_AGENT_REASON` for `item view`; the server sets it automatically.
Review what the agent has accessed with:

```sh
pass-cli agent monitor protonpass-mcp
```

Renew the token with `pass-cli agent renew` before it expires.

## Tool inputs

### `create_alias`

```json
{
  "prefix": "github"
}
```

### `search_aliases`

```json
{
  "query": "github",
  "page": 0
}
```

`page` is optional and defaults to `0`. Each page contains at most 20 matches.
Results include only the alias address, display name, and enabled state.

### `create_login`

```json
{
  "title": "GitHub",
  "email": "github-alias@example.com",
  "urls": ["https://github.com"],
  "passwordLength": 24,
  "includeUppercase": true,
  "includeSymbols": true
}
```

At least one of `username` or `email` is required. The password length defaults
to 24. The login result confirms that a password was generated but deliberately
does not reveal it.

### `get_or_create_alias_contact`

```json
{
  "alias": "github-alias@example.com",
  "contact": "support@example.org"
}
```

The result includes `reverseAlias`, the address to use when sending mail from
the alias to that contact. If the contact already exists, the same operation
returns its reverse alias with `created` set to `false` and `existed` set to
`true`.

### `get_totp`

Select the login with exactly one of `itemId` or `itemTitle`:

```json
{
  "itemTitle": "GitHub",
  "field": "Authenticator"
}
```

`field` is optional and is useful when an item has multiple TOTP fields.
`get_totp` returns the current codes and their field metadata, but never returns
the underlying TOTP secret.

### `find_logins`

```json
{
  "query": "kalibrr",
  "url": "https://www.kalibrr.com/login"
}
```

Both filters are optional. `query` is a case-insensitive title substring. `url`
is a web URL or bare domain; it matches a login when the page's host is a saved
URL's host or one of its subdomains (a leading `www.` on the saved URL is
ignored, so a saved `https://www.kalibrr.com` matches `kalibrr.com`). Results
contain `id`, `title`, `hasUsername`, `hasEmail`, and `urls`.

### `get_login_credentials`

Select the login with exactly one of `itemId`, `itemTitle`, or `url`:

```json
{
  "url": "https://www.kalibrr.com/login"
}
```

`itemTitle` is matched case-insensitively against the full title. When a title
or `url` matches no login or more than one, the call is refused; for several
matches, the message lists their IDs and titles so one can be chosen by
`itemId`. Use the revealed password only to fill the sign-in form; never repeat
it to the user or into a transcript.

## Configuration

- `PROTONPASS_CLI_PATH`: Proton Pass CLI executable; defaults to `pass-cli`.
- `PROTONPASS_TIMEOUT_MS`: command timeout in milliseconds; defaults to 60000.
- `PROTONPASS_AUDIT_LOG`: credential reveal audit log; defaults to
  `$XDG_STATE_HOME/protonpass-mcp/audit.log`, or
  `~/.local/state/protonpass-mcp/audit.log` when `XDG_STATE_HOME` is unset.
- `PROTONPASS_REVEALS_PER_HOUR`: maximum `get_login_credentials` reveals per
  rolling hour; a positive integer, defaulting to 5 (invalid values use 5).
- `PROTON_PASS_SESSION_DIR`: read by Proton Pass CLI itself; point it at the
  dedicated agent session directory described above.
- `SIMPLELOGIN_API_KEY`: SimpleLogin API key required by `search_aliases` and
  `get_or_create_alias_contact`.
- `SIMPLELOGIN_API_BASE_URL`: API base URL; defaults to
  `https://app.simplelogin.io` and can be changed for self-hosted SimpleLogin.
- `SIMPLELOGIN_TIMEOUT_MS`: SimpleLogin request timeout in milliseconds;
  defaults to 60000.

The server invokes Proton Pass CLI directly without a shell and calls
SimpleLogin over HTTPS (or loopback HTTP for local self-hosting). It writes
protocol messages only to stdout and does not log tool arguments, API keys, CLI
output, or SimpleLogin API responses. The credential audit log records reveal
attempts but never credential values. Error messages never include CLI stdout;
when a Proton Pass CLI command fails, the message gives its exit code and one
line of its stderr, with email addresses and token-like strings redacted.
